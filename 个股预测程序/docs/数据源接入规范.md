# 数据源接入规范

> 这份规范来自**真实踩坑**，不是理论。每一条都对应一次具体事故，请照着做。

## 为什么需要它

本项目曾反复出现同一类问题：**数据看起来正常，结论却是错的**。

| 事故 | 表面现象 | 真实原因 |
|---|---|---|
| 开户数用了 2023-08 的数 | 有数字、能算分 | 上游停更，程序不知道 |
| CPI/PPI 用了 2025-09 的数 | 有数字、能算分 | 上游停更 |
| PPI 报 +5.0%（实为 +2.3%） | 有数字、字段名看着对 | `BASE_SAME` 是**当月**同比，不是累计 |
| 板块历史只到 2024-01-08 | 有数据、能出预测 | akshare 默认参数硬编码 `end_date='20240108'` |
| 板块历史探测报 EMPTY | 看起来数据源不可用 | 其实是**我的探测函数写错了**（DataFrame 当 dict） |

共同点：**程序没崩，数据不缺，但结论错了**。这类问题代码自测抓不到，必须靠机制拦截。

## 新增一个外部数据源，必须做四件事

### ① 登记新鲜度

在 `core/freshness.py` 的 `SOURCES` 里加一行：

```python
SOURCES = {
    "your_source": ("中文名", "daily", "数据提供方"),
}
```

频率取值：`daily`(5天) / `weekly`(14天) / `monthly`(70天) / `quarterly`(130天)。

日频给 5 天是因为要跳过周末和小长假，不是 1 天。

**然后在取数的代码路径里调用校验**：

```python
from . import freshness as FR
FR.validate("your_source", df["date"].max())
```

- 取不到日期 → 状态为 `unknown`（**不可验证 ≠ 新鲜**），不要当新鲜处理
- 过期 → 状态为 `stale`，**必须排除出计算**，只在界面标注原因

### ② 标注统计口径

凡是涉及**同比 / 环比 / 累计 / 定基 / 当月 / 季调**的字段，必须在 `core/macro_source.py` 的 `CALIBER` 里写清三件事：

```python
CALIBER = {
    "ppi": (
        "统计局口径，**累计同比**（年初至当月的同比）",      # 这个数字到底是什么
        "字段 BASE_ACCUMULATE（定基指数），换算：值 − 100",   # 从哪来、怎么算
        "当月同比见 mom_same",                              # 易混点的提示
    ),
}
```

**这条最容易被忽略，也最危险**：`BASE_SAME` 里的 `SAME` 确实是"同比"，但它指**当月**同比；要累计同比得用 `BASE_ACCUMULATE`（定基指数形式，102.3 表示 +2.3%）。

代码无法自测出这种错误——数据是正确返回的，只是口径不符。**只有把口径显示在界面上、让人核对才能发现**。

### ③ 审计脚本加一项

在 `tests/audit_sources.py` 的 `main()` 里加一个探测函数，并加入 `items` 元组：

```python
def _your_source():
    from core import your_module as YM
    obj = YM.fetch("...")
    if obj is None:
        raise NoData("确实没有数据，原因：…")   # 确认调用方式正确时才用 NoData
    return obj                                  # 让 extract_latest_date 去解析
```

**关键：区分 `NoData` 和异常**

| 你抛的 | 状态 | 含义 |
|---|---|---|
| `NoData("…")` | `NO_DATA` | 数据源确实没数据（调用方式已验证正确）|
| `ShapeError`（提取器自动抛）| `SHAPE_ERROR` | 拿到了数据但解析不出日期 → **基本是代码写错** |
| 其他异常 | `CALL_ERROR` | 调用直接失败 → **基本是代码写错** |

后两类会打印诊断（实际类型、可用列名、异常原文）。**只要出现它们，退出码非 0**——先去修脚本，不要怀疑数据源。

### ④ 定义失败降级路径

每个数据源都必须回答：**这个源失败时，程序怎么办？**

| 降级方式 | 适用 | 示例 |
|---|---|---|
| 换备用源 | 有等价数据源 | 板块历史：同花顺 → 东财 → 新浪 |
| 手工输入 | 数据低频、人工可得 | 宏观数据：东财 → akshare → **手动填写** |
| 明确缺失 | 无替代 | 开户数：标注过期，**不输出分数** |

**绝对不允许**：静默返回旧数据、用上次缓存冒充当前、拿默认值顶替。

## 一条经验

**"有数据"和"数据可用"是两件事。**

程序最容易犯的错，不是崩溃，而是**自信地用一个错误的数字算出看起来合理的结论**。

所以判断标准不是"程序没报错"，而是：
1. 这个数字**新鲜**吗？（新鲜度校验）
2. 这个数字的**口径**是我要的吗？（口径标注 + 人工抽查）
3. 数据源挂了程序**会说实话**吗？（降级路径 + 界面暴露）

三条都过，才算接好一个数据源。

## 排查顺序：先怀疑自己，再怀疑对方

数据不对时，**按这个顺序查，不要跳步**：

```
① 我的调用  →  ② 对方接口  →  ③ 数据本身
```

### ① 我的调用（占比最高，先查这里）

| 检查项 | 真实案例 |
|---|---|
| **函数签名 / 默认参数** | `stock_board_industry_index_ths` 默认 `end_date='20240108'`，不传日期就永远只到 2024-01-08。曾被误判为"数据源停更" |
| **返回类型** | `fetch_nav_history` 返回 **DataFrame**，被当成 dict 取键 → 报"无数据" |
| **模块找对了吗** | 财务数据在 `core.fundamental`，不在 `core.datasource` |
| **列名/键名** | 财务表的日期列叫「报告期」不是「日期」；LPR 的日期列叫 `TRADE_DATE` |
| **字段含义** | `BASE_SAME` 是**当月**同比，累计同比要用 `BASE_ACCUMULATE` |

**五次事故里有五次都在这一层。** 这一层的错误有个共同特征：**看起来像数据源不可用**，实际是自己写错了。

### ② 对方接口（参数对、类型对，但拿不到想要的数据）

- 需要显式参数（日期区间、分页、市场代码）
- 字段名与文档不符（上游改版）
- 上游停更（数据止于某个日期）
- 网络/地区限制（如东财 `push2his` 本机不可达）

验证方法：**用最小可复现的请求**（curl / requests 直连）确认接口本身返回什么，绕开自己的封装层。

### ③ 数据本身（前面都对，数据质量有问题）

- 数据过期 → 走新鲜度校验
- 口径不符 → 走口径标注
- 数值异常 → 交叉验证（如 PPI 累计 vs 当月）

### 为什么顺序不能反

如果先假设"数据源坏了"，会：
- 花大量时间去换源、逆向协议、写解析器
- 而真正的原因可能只是一行默认参数

**真实代价**：我为了"同花顺板块历史停更"这个问题，一度准备去**逆向它的专有压缩格式**（解 `price`/`volumn` 字符串，工作量很大）。结果先花一条命令看了函数签名——问题是一行默认参数。

**一句话**：越是想动手解决复杂问题，越要先验证最简单的可能。

### 落到实践

排查时先把这三行写下来再动手：

```
1. 我的调用正确吗？（签名/类型/模块/列名/字段含义）
   → 验证方式：打印 type()、list(columns)、inspect.signature()
2. 对方接口返回什么？（用最小请求直连验证，绕开封装）
   → 验证方式：requests 直连，看原始 JSON/HTML
3. 数据本身可用吗？（新鲜度/口径/合理性）
   → 验证方式：与其他源交叉对比、看日期分布
```

**在审计脚本里，这三层分别对应**：`CALL_ERROR`/`SHAPE_ERROR`（第①层）、`NO_DATA`（第②层）、`STALE`（第③层）。这也是为什么审计要区分这三种状态——**它直接告诉你该去查哪一层**。

## 附：从页面 JS 挖出真实报表名

东财 datacenter 的 `reportName` 猜不出来时，正确做法是**从页面加载的 JS 里挖**：

```python
import re, requests
H = {"User-Agent": "Mozilla/5.0 Chrome/122", "Referer": "https://data.eastmoney.com/"}
html = requests.get("https://data.eastmoney.com/cjsj/gpkhsj.html", headers=H).text
js = re.findall(r'src="([^"]+\.js[^"]*)"', html)
found = set()
for u in js[:12]:
    if u.startswith("//"):
        u = "https:" + u
    elif u.startswith("/"):
        u = "https://data.eastmoney.com" + u
    found |= set(re.findall(r"RPT_[A-Z0-9_]{4,}", requests.get(u, headers=H).text))
print(sorted(found))       # → ['RPT_STOCK_OPEN_DATA']
```

**三个关键点**：

1. 静态 HTML 里通常**没有** `RPT_` 字面量（数据由 JS 渲染），必须下载 JS 再搜。
2. 排序列名也要试：该报表排序列是 `STATISTICS_DATE`，不是 `REPORT_DATE`；
   用错会返回「排序列不存在」。
3. 不确定列名时，**先不带排序参数**拿任意一行，看真实键名，再决定怎么排序。

用这套方法一次定位到开户数的真实接口，避免继续猜 `RPT_ACCOUNT_STATISTICS`
这类不存在的名字（之前猜了 8 个全失败）。

## 案例：新增开户数（自动获取不可行 → 用代理指标）

这是本项目**唯一确认"无法自动获取"**的数据，排查路径完整记录如下。

### 试过的 8 条路径

| # | 路径 | 结果 |
|---|---|---|
| 1 | `ak.stock_account_statistics_em` | 止于 2023-08 |
| 2 | 东财 `RPT_ACCOUNT_STATISTICS` 等 8 个猜测名 | 报表配置不存在 |
| 3 | 东财 `RPT_STOCK_OPEN_DATA`（JS 挖出的正确名）| 止于 2023-08（同源）|
| 4 | 上交所 `query.sse.com.cn` 各 sqlId 猜测 | 返回空 JSON（`isPagination:false`，无数据）|
| 5 | 上交所 投资者统计页 | 200，但页面无 sqlId/数据文件线索 |
| 6 | 深交所 `ShowReport?CATALOGID=1803_sczm` | 证券类别统计，非开户数 |
| 7 | 中国结算 统计月报页 | 200，但无文件直链（JS 渲染）|
| 8 | 中登月报目录 `/zdjs/editor_file/` | 404 |

### 结论

**中登已停止公开发布月度新增投资者数**；交易所口径（A股新开户）虽有发布，
但接口不公开、需爬 JS 或人工下载 Excel。**自动获取不可行**。

### 口径提醒（易混，来自用户提供）

| 说法 | 实际含义 | 发布方 |
|---|---|---|
| 新增投资者数 | 一码通新账户（**人**）| 中国结算 |
| A股新开户数 | 新开 A股股票账户（**含一人多户**）| 上交所/深交所 |
| 两融新开户 | 新开信用账户 | 中国结算/交易所 |
| 期末投资者数 | 累计未注销未休眠 | 中国结算 |

两者差一个数量级逻辑：中国结算 2025 全年新增投资者 1386.95 万；
上交所 2026 前三季度 A股新开账户 2712.59 万户（账户口径，含重复开户）。
**混用会得出荒谬结论。**

### 替代方案：散户入场热度（代理指标）

开户数本质测的是"散户入场意愿"，可用同样含义、且**日频新鲜**的指标代理：

| 代理项 | 数据源 | 权重 |
|---|---|---|
| 成交额 20 日均值 / 120 日均值 | 日线（新鲜）| 1.0 |
| 振幅热度（20 日 / 60 日平均振幅）| 日线（新鲜）| 0.7 |
| 两融余额 20 日变化 | `stock_margin_account_info`（新鲜）| 1.0 |

合成 0~100 分，分档：过热（≥80）/ 偏热（≥62）/ 中性 / 偏冷 / 冰点（≤20）。
**过热偏空、冰点偏多**（反向指标），与开户数的用法一致。

**必须遵守的一条**：代理指标要在界面上明确标注「这是代理指标，不是开户数」，
不能冒充满开户数。代理的价值在"及时"（日频 vs 月频），不在"精确等同"。
